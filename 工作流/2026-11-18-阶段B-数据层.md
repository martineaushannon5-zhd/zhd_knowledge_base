# 阶段 B 数据安全底座 — 验证报告

日期：2026-11-18。范围：文件真相源数据层（独立模块，未接入 UI；UI 接入属阶段 C）。所有验证用临时目录，未触碰用户真实资料。

## 交付模块（spike/electron/electron/vault/）

| 模块 | 职责 |
|---|---|
| atomic.cjs | 原子写入（同目录临时文件+fsync+rename，失败不静默覆盖）、sha256、路径穿越/绝对路径/符号链接防护、大小上限 |
| frontmatter.cjs | Markdown + YAML frontmatter 解析/序列化（js-yaml JSON_SCHEMA），字段校验，FrontmatterError |
| search-index.cjs | better-sqlite3 FTS5 派生索引；确定性 CJK 二元组预分词（索引/查询同一套，版本 cjk-bigram-1）；可全量重建 |
| store.cjs | VaultStore：笔记 CRUD、revision 冲突保留、损坏文件隔离、JSON 元数据（revision）、附件内容寻址去重、索引重建/检索 |
| backup.cjs | 全量备份（逐文件 sha256+size 清单，排除派生索引）；恢复先 staging 校验哈希/路径再切换，保留原 vault，重建索引 |

## vault 目录布局

```
<vault>/
  vault.json                 # kind/schema_version/createdAt
  notes/<id>.md              # 真相源：frontmatter + Markdown 正文
  notes/.corrupt/            # 损坏 frontmatter 隔离区
  notes/.conflicts/          # 冲突时保留的传入版本副本
  metadata/{collections,tags,settings}.json   # 非正文真相源，带 revision
  attachments/<sha256>/blob  # 内容寻址单 blob，原始文件名在引用里
  index.sqlite               # 派生 FTS5，可删除重建
```

## 验证结果（tests/vault.test.ts，14/14 通过）

- frontmatter 往返一致；缺失/非法 frontmatter 抛 FrontmatterError。
- 分词器对中文产生二元组，2 字查询可匹配。
- 笔记保存/读取/列表，revision 递增，createdAt 保留。
- 冲突：外部把文件改到 rev2 后，用 baseRevision=1 保存 → ConflictError；磁盘版不被覆盖，传入版写入 .conflicts 副本。
- 损坏 frontmatter 被隔离到 .corrupt 并报告，健康笔记不丢。
- 软删除 status=trashed，默认检索排除、includeTrashed 可见。
- 元数据 JSON 真相源读写 + revision 冲突检测。
- 附件按 sha256 内容寻址去重（同内容两次添加只有一个 blob），保留中文原始文件名；整库复制到新目录后相对路径仍可解析（迁移）。
- 删除 index.sqlite 后从 Markdown 自动/显式重建，中文检索恢复。
- 备份→恢复到新目录：笔记/元数据/附件哈希一致，索引重建；派生索引不进备份。
- 备份文件被篡改 → 哈希校验失败中止，目标目录不被创建。
- 恢复覆盖已有 vault → 原库保留到 .old 目录可回退。
- 伪造 manifest 含 `../evil.txt` → 路径穿越拒绝，目标不受影响。

## 设计取舍与边界（诚实记录）

- 中文分词用确定性 CJK 二元组基线，使 1–2 字查询可用；召回质量与一万篇 P95 基准、jieba 升级属阶段 C。
- 备份为目录+manifest 全量形式；ZIP 导出与增量备份后置。
- 跨文件变更（笔记+元数据+附件）目前各自原子写入，尚未实现操作 ID/提交清单/崩溃恢复日志；data-model 中该协议仍标待完善，阶段 C/F 补。
- 数据层尚未通过 IPC 接入渲染进程，UI 仍用原型 JSON 存储；接入与捕获/搜索闭环属阶段 C。
- 保留策略（最近 7 份备份、软删 30 天清理）未自动执行，需 Owner 确认，符合 data-model。

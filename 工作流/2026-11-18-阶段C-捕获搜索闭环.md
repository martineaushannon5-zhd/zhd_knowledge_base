# 阶段 C 捕获→编辑→中文搜索闭环 — 验证报告

日期：2026-11-18。范围：把阶段 B 的 vault 数据层经受限 IPC 接入 UI，跑通捕获→编辑→自动保存→中文搜索→回收站闭环，并建立一万篇搜索基准。

## 交付

### 主进程 / 预加载
- electron/vault-bridge.cjs：注册 kb:list/save/remove/restore/purge/search/rebuild/info/export 处理器，全部经 assertSender 校验来源，委托 VaultStore（路径安全/校验/原子写/revision 冲突由数据层负责）。
- main.cjs：在 userData/zhd-vault 打开 vault，注册桥接，退出时关闭。
- preload.cjs：暴露 window.kbStore（contextIsolation+sandbox 不变）。

### 渲染进程
- src/data.ts：存储适配层。Electron 走 kbStore（文件真相源），浏览器预览保留 localStorage 回退。统一按笔记操作：listAll/persistNote/trashNote/restoreNote/purgeNote/searchNotes/exportAll。
- src/App.tsx：
  - 自动保存：编辑停止输入 1.5 秒后自动持久化；保存状态机 idle/saving/saved/error/conflict，顶栏可见。
  - 冲突：vault 抛 ECONFLICT 时显示"外部已修改"，不覆盖磁盘版。
  - 回收站：软删除→回收站视图→恢复/彻底删除（二次确认，文件级移除）。
  - 搜索：桌面走 SQLite FTS5（中文二元组分词），浏览器走关键词过滤；防抖 200ms。
  - 设置：显示存储方式、重建索引、导出 JSON。
  - 修复一个真实 bug：空笔记校验此前被默认标题"未命名笔记"绕过，已改为校验原始输入。

## 一万篇搜索基准（scripts/benchmark.cjs，真实运行）

- 语料：固定种子 20261120，10000 篇，正文约 2KiB（总约 20.98MB），4 集合均匀，24 标签池，混中英/代码/数字/标点。生成器版本 bench-corpus-1。
- 环境：win32 x64，Node 24.14.1，better-sqlite3 13.2.0，分词器 cjk-bigram-1。
- 查询：固定 100 条（40 中文含 1/2/多字、20 中英混合、20 标签/集合、10 特殊字符、10 无结果），预热 20 次，10 轮共 1000 样本。
- 计时口径：`await vault.search(q,{limit:10})` 墙钟时间，含分词 + SQLite FTS5（**后端检索延迟，不含 IPC 与 React 渲染**）。
- 结果：**P95 = 37.15ms**（预算 500ms，达标），中位数 14.33ms，最大 47.95ms，**错误 0**，特殊字符 0 抛错。
- 召回：**Recall@10 均值 0.997**（80 条相关性查询，ground truth 按构造期子串匹配）。
- 索引重建 3.5s；index.sqlite 约 51.8MB。
- 结果文件：test-results/benchmark.json（含每条查询命中/召回与全部元数据）。

## 边界与诚实记录

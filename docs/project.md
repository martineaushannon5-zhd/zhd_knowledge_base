# 项目工作模型

> 当前已有Windows交互原型（spike/electron），正式数据层和安装包尚未完成。阶段仅为可验收节点，不是工期或发布日期承诺。
> Agent 工作规则唯一引用 `AGENT-规则.md`；本文件记录实施指导，不复制硬规则。

## 1. 项目原则

1. **主线优先**：任何功能都要能挂到主线上；挂不上的，进能力池等待。
2. **J2 > J1 > J3**：先保证随时记、随时找回；再约束 Agent；最后做驾驶舱。
3. **Windows 优先**：先验证桌面主线，Web 后置，鸿蒙纳入后续评估。
4. **本地优先**：数据默认在本地；可导出、可备份、可迁移。
5. **工作契约**：仅引用 `AGENT-规则.md`，按任务风险选择工作载体。
6. **连续性**：以当前节点、验证证据和下一步衔接工作。

### 顾问推荐基线（尚未实测）

这不是用户已明确批准具体框架或验证通过的结论；以 T-001 的 Windows spike 结果决定保留或调整，不三栈并建。

| 层 | 推荐与理由 | 待验证 |
|---|---|---|
| 桌面与界面 | Electron + TypeScript + React + Vite；CodeMirror 6 编辑器，沿用 TS 生态 | 中文输入、启动资源、长文编辑 |
| 文件边界 | 主进程负责文件 IO；渲染进程通过受限 preload/IPC 调用，不直接获得 Node 能力 | 路径约束、异常和崩溃恢复 |
| 数据 | Markdown/frontmatter + JSON 元数据为真相源；SQLite/better-sqlite3 FTS5 为派生索引 | 原子保存、重建、原生模块打包 |
| 中文搜索 | 应用层分词后写入/查询 FTS5，分词器由 spike 验证 | 召回、高亮映射、性能 |
| 测试与分发 | Vitest 单元测试 + Playwright Electron 流程测试；electron-builder NSIS | Windows 安装/卸载与打包后数据库可用 |

Web 后置，共享纯 TS 领域类型、数据协议和适用 UI；文件 IO、数据库、秘密访问使用平台适配层，不要求共享全部 Node 逻辑。鸿蒙浏览器/PWA/原生路线待真机验证，不承诺 PWA 可安装。AI 模型路线另评估，不阻塞存储、备份和关键词搜索。

## 3. 工作模型：主线 + 能力池

```text
主线：Windows 最小验证 → 数据与备份 → 捕获/编辑/搜索 → Agent交接 → 基础知识库AI → Windows交付
能力池：随时拉取，不预设顺序；每张能力卡独立验收
```

- **主线**：必须端到端贯通。任何平台、任何技术选型，都不能让主线断掉。
- **能力池**：功能卡片。想做就拉一张，做完更新状态；不承诺顺序和日期。
- **阶段可验收**：按节点推进，不绑定时间；L 编号是追踪标识，不表示执行顺序，L6 备份先于 L4 AI。

## 6. 分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| Owner（郑泓达） | 目标、优先级、验收、密钥、最终决策 | 不替 Agent 做重复执行 |
| 执行 Agent（多个工具，不固定品牌） | 文档、代码、测试、脚本、文件修改；共用 `AGENT-规则.md` 契约 | 不替 Owner 拍板技术选型和优先级 |
| KB-Agent（知识库管理员） | 检索、问答、总结、按模板输出、生成 Context Pack | 不写代码、不改业务仓库、不删历史 |
| Code-Agent（编码 Agent） | 按任务卡改代码、跑测试、写回报告 | 不自行扩大范围；规则和秘密操作以明确授权为准 |
| Automation | 索引、备份、同步、检查 | 不改内容、不改权限 |

## 7. 工作方式与连续性

工作规则仅引用 `AGENT-规则.md`。本项目工作载体：只读分析无需任务卡；低风险修改以明确用户请求为依据；多步实施或交接使用任务卡。没有匹配能力不阻塞工作；只核验相关事实，可验证后使用，不能验证且影响当前操作时说明阻塞。

开始时定位主线、相关需求和最近证据；结束时简明给出结果、验证、下一步，无问题不强问。需要交接时记录任务范围、未完成项和验证证据；仅在已授权范围更新文件，不自动扩展到其他状态文档。暂停后从当前节点和最近报告继续。

## 8. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 推荐基线未经验证 | 主线落地受阻 | T-001 单栈最小验证，记录失败证据再调整，不三栈并建 |
| 功能蔓延 | 主线散 | 新功能必须挂主线或进能力池；四问不过不做 |
| Agent 范围蔓延 | 连锁 bug、上下文爆炸 | 任务卡写死允许文件、测试范围、上下文预算 |
| 秘密泄露 | 数据/账号风险 | 只存路径引用；`.gitignore` + secret scan；不回显 |
| 平台顺序倒置 | 架构返工 | 桌面先跑通主线；Web/手机只做适配层 |
| 单人项目失忆 | 回来接不上 | 主线 + 当前状态 + 工作流报告 + 决策记录 |

T-001交互原型已完成窗口与原型存储验证，SQLite及安装包未完成；后续正式实现节点未开始。以下是验收顺序而非时间承诺。

| 阶段 | 工作 | 退出证据 |
|---|---|---|
| T-001 Windows 最小验证（当前下一步） | 单一推荐栈跑通最小窗口、临时文件IO、SQLite FTS5可用性、原生模块与NSIS打包 | 环境/版本、实际命令与结果；开发及安装后IO/SQLite可用；失败与资源测量记录 |

| 搜索与桌面主线 | L3/L7：检索、标签集合、响应式桌面布局 | acceptance.md 可复现基准与主流程通过 |
| Agent交接 | L5：现有文档模板验证真实任务闭环 | 连续3次任务验证；可手工提前试用 |
| 基础AI | L4：关键词检索生成带引用 | 引用可追溯、无依据拒答；模型授权未定不阻塞此前节点 |

T-001只验证环境、文件IO、SQLite与打包风险，不构建完整产品或同时搭建其他桌面壳。编辑器、可靠保存和中文搜索质量分别在后续节点验证。现有任务卡已更新，尚未执行或安装依赖。详细实施顺序与提示词见 `实施路线与Agent提示词.md`。

## 10. 不做什么

- 不做编码 Agent 本身；编码 Agent 是外部角色。
- 不做公有云 SaaS、多人协作、插件市场。
- 不把手机端作为第一平台。
- 不为了“完整”新增 Owner 没要求的功能。
- 阶段只表示可验收节点，不设周数、不承诺发布日期。

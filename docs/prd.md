## 1. 背景与问题

Owner 是单人全栈工程师，正在推进 yoji（英语 ArkTS App）后台等项目。当前的核心问题不是“没有笔记工具”，而是：

1. **灵感易失**：想法、规范、决策散落在聊天、代码、临时文件里，过了当下就找不回。
2. **Agent 不可控**：编码 Agent 会做无用功能、难以理解的功能（例如后台审计），回答格式漂移。
3. **连锁风险**：改一个 bug 可能引发新 bug；测一个功能时顺手测别的，导致上下文爆炸。
4. **事实过期**：服务器、云账号、仓库、端口等信息会变；Agent 可能拿旧信息行动。
5. **秘密边界**：知识库需要让 Agent 找到服务器/云资源，但不能把明文密钥写进 Git 或回答里。
6. **平台缺失**：桌面、Web、手机没有统一入口；换电脑后恢复成本高。

## 3. 非目标

| 不做 | 原因 |
|---|---|
| 编码 Agent 本身 | 已有外部编码 Agent；本项目做管理员与约束层 |
| 公有云 SaaS / 多人协作 | 单人本地优先；复杂度高 |

## 6. 功能范围与优先级

优先级口径：

- **P0**：主线必须贯通，或数据/安全有风险。
- **P1**：主线之后的高价值能力，不阻塞第一版。
- **P2**：远期/高成本/依赖外部条件。

## 7. 业务规则

| 规则 | 内容 |
|---|---|
| 捕获 | 默认进 Inbox；2 秒防抖自动保存；崩溃后可恢复 |
| 整理 | 集合单层；标签多对多；标题可重复，ID 唯一 |
| 搜索 | 中文分词；特殊字符转义；无结果给建议 |
| Agent 工作契约 | 仅引用 `AGENT-规则.md`，不在 PRD 复制硬规则；验收映射见 acceptance.md |
| 工作载体 | 只读无需任务卡；低风险修改依据明确用户请求；多步实施/交接使用任务卡 |
| 能力与事实 | 无匹配能力不阻塞；相关事实可验证后使用，无法验证且影响当前操作才阻塞 |
| 删除 | 软删除 30 天；彻底删除需二次确认 |
| 备份 | 每日自动 + 手动；恢复演练；导出不依赖应用 |
| AI | 只服务知识库；带引用；无依据拒答；不写代码 |
| 平台 | 桌面 → Web → 手机；核心逻辑复用 |

## 9. 数据、隐私与安全

- 数据默认存本地；不上传全库。
- Markdown/frontmatter 与 JSON 元数据共同为真相源；索引是派生数据，可重建。原子写入、附件引用和恢复校验见 data-model.md。
- 知识库只存 `secret_ref`（本地路径 + 键名），不存明文；本地秘密文件按 Owner 选择可为明文，但不进知识库、不进 Git。
- 秘密文件在仓库外；`.gitignore` + pre-commit secret scan。
- AI 读取秘密需任务显式授权；回答/报告只写引用。
- 敏感事实标记 `sensitivity=secret`，默认不进 Git、不默认进 AI 上下文。
- 删除软删 30 天；备份保留策略待定。
- 如果秘密可能进入 Git 历史，立即轮换。

## 10. 平台顺序与技术约束

| 顺序 | 平台 | 首要目标 |
|---|---|---|
| 1 | 桌面端 | 主工作台；本地文件访问；安装包 |
| 2 | Web 端 | 浏览器访问；跨设备阅读/编辑 |
| 3 | 手机端 | 捕获、阅读/搜索、编辑长文；鸿蒙纳入评估，路线待真机验证 |

顾问推荐基线（尚未实测，并非用户已明确批准具体框架）：Electron + TypeScript + React + Vite + CodeMirror 6；主进程文件 IO；Markdown/frontmatter + JSON 元数据真相源；SQLite/better-sqlite3 FTS5 派生索引，应用层中文分词由 spike 验证；Vitest + Playwright + electron-builder NSIS。

当前下一步为 T-001 Windows 最小验证，不三栈并建。实施节点见 project.md，阶段不是时间承诺。先完成存储和备份恢复，再接基础 AI；备份不被 AI 选型阻塞。Web 后置；鸿蒙纳入评估，浏览器、PWA、原生路线待真机验证，不承诺 PWA 可安装。共享领域类型和协议，不要求共享全部 Node 逻辑。

## 11. 验收

详细验收见 `docs/acceptance.md`，其中定义固定语料、查询集、硬件记录、计时/P95 口径及性能边界；上述指标均为目标，尚未实测。Windows 首版独立验收，不等待 Web/鸿蒙。总原则：

# 验收标准

> 验收不是“功能看起来有了”，而是“主线贯通、Agent 可控、数据不丢、秘密不泄、格式稳定”。
> 详细证据写 `工作流/` 报告；本文件只列验收项和通过标准。

## 1. 验收原则

| 原则 | 说明 |
|---|---|
| 结果先行 | 先看做完没有、到哪一步，再看细节 |
| 可复现 | 验收步骤要能重复；不能靠“我记得” |
| 证据在报告 | 截图、命令输出、测试结果放 `工作流/` |
| 失败处理 | 阻断数据安全或当前节点的失败先修复；无关待办不阻塞独立节点 |
| 阶段 | 仅表示可验收节点，不是时间承诺；所有性能指标为待验证目标 |

## 2. 主线验收

| 节点 | 通过标准 | 验收方式 |
|---|---|---|
| L1 捕获 | 桌面端 10 秒内完成一条；2 次点击内；自动保存；崩溃恢复 | 实测 10 次 |
| L2 本地存储 | Markdown/frontmatter + JSON + 附件可读；目录可迁移；删索引可重建；外部冲突保留双方 | 手动检查 + 重建 + 原子保存/冲突故障注入 |
| L3 搜索 | 中文关键词；标题/正文/标签；1 万篇 P95 < 500ms；高亮 | 基准测试 + 样本集 |
| L4 知识库 AI | 回答带引用；无依据拒答；不写代码；按模板输出 | 20 个问题抽检 |
| L5 Agent 循环 | 任务卡 → Context Pack → Code-Agent → 工作流报告；越界即停 | 连续 3 次任务 |
| L6 备份/导出 | 先于 AI 验收；临时目录校验 hash/schema/引用，失败不覆盖原库；MD/ZIP/JSON 可导出 | 恢复演练 + 损坏备份/共享附件用例 |
| L7 桌面 UI | 三栏布局；键盘操作；状态可见；无阻断性 bug | 主流程走查 |
| L8 Web 端 | 核心 CRUD/搜索可用；响应式 | 浏览器走查 |
| L9 手机端 | 捕获、阅读/搜索、编辑长文可用 | 真机走查 |

## 4. Agent 契约验收

工作规则唯一引用 `AGENT-规则.md`；本节是验收映射，不复制读取顺序、秘密访问或停止条件等硬规则。

| 检查项 | 验收证据 |
|---|---|
| 工作载体 | 只读无需任务卡；低风险修改可追溯到明确用户请求；多步实施/交接有任务卡 |
| 能力与事实 | 无匹配能力如实说明但不阻塞；仅核验相关事实，可验证后使用；影响操作且无法验证才记录阻塞 |
| 范围 | 变更/验证与本次授权一致，未擅自扩展 |
| 输出 | 简明结果、验证、下一步，不固定四行；无问题不强问，有待决策问题才提出 |
| 报告 | 必要字段齐全，条件字段适用时填写，未执行如实说明 |

报告必要字段：请求或任务标识、结果、修改文件/范围、验证（方法、结果、未执行原因）、未完成项、下一步。条件字段：测试详情（有测试）、Git/推送（涉及版本操作）、工具（影响复现时）、风险/问题/决策（存在时）、进度（多步交接时）。不要求为每次只读查询生成报告文件。当前项目未初始化 Git；涉及该字段时写“未初始化 Git／不适用”，不能写“干净”或“已推送”。

连续 3 次真实适用任务通过才算契约稳定；文档修订不等于实测通过。

## 5. 秘密管理验收

| 检查项 | 通过标准 |
|---|---|
| 文件级扫描 | 使用文件级 secret scanner 扫描知识库、待交付文件、导出与报告；包含未跟踪文件，不以 `git grep` 替代；不读取外部秘密文件、不回显命中值 |
| `.gitignore` | Git 初始化后检查秘密文件、`.env`、本地配置排除；未初始化如实记不适用，排除不等于完成扫描 |
| secret scan | 记录工具/版本、扫描范围、排除项、退出码及脱敏结果；Git 历史扫描仅在存在仓库时附加 |
| 知识库 | 只出现 `secret_ref`，不出现明文 |
| AI 回答 | 不回显；只说“已读取/已使用” |
| 报告 | 只写引用和用途，不写值 |
| 权限 | 只读必要文件；最小权限 |
| 泄露处理 | 如进入 Git 历史，立即轮换 |

## 6. 平台验收

Windows 首版独立验收，不等待 Web 或鸿蒙。推荐工具为 Vitest + Playwright + electron-builder NSIS，尚未运行；当前下一步 T-001 最小验证，阶段退出项见 project.md。

### 桌面端（Windows）

- NSIS 安装包可安装/卸载；打包后 better-sqlite3 原生模块可用；启动目标 < 3 秒。
- 本地文件访问正常；目录可换。
- 三栏布局；键盘操作；状态可见。
- 备份/恢复可用。

### Web 端

- 主流浏览器可用；响应式。
- 核心 CRUD/搜索可用。
- 不要求本地文件系统能力；通过服务端/本地服务桥接。

### 手机端

- 捕获、阅读/搜索、编辑长文可用。
- 鸿蒙待真机验证系统/浏览器版本、输入、文件访问、离线持久化和安装能力，不承诺 PWA 可安装。
- 弱网/离线策略明确；数据不丢。
- 触控目标 ≥44px；安全区适配。

## 7. 非功能验收

| 类别 | 通过标准 |
|---|---|
| 性能 | 捕获 < 1 秒；搜索 1 万篇 P95 < 500ms；启动 < 3 秒 |
| 可靠性 | 杀进程 20 次不丢已保存内容；备份恢复一致 |
| 安全 | 无明文秘密；XSS 清洗；依赖审计；默认无外联 |
| 隐私 | AI 默认只读选中内容；不上传全库 |
| 可访问性 | 键盘可达；对比度 AA；焦点可见 |
| 可移植 | Markdown + 附件 + JSON 元数据可导出 |
| 可维护 | 文档、模板、报告、决策记录齐全 |

### 可复现搜索基准与性能边界（待实施）

- 固定种子生成 10,000 篇非敏感 Markdown：每篇正文约 2 KiB、标题 10–30 字、3 个标签，中英混排，包含代码、数字和标点；保存生成器版本、种子、语料/查询集 hash。附件内容/OCR、向量检索和网络模型不计入本基准。
- 固定 100 条查询：中文 40、混合词 20、标签/集合筛选 20、特殊字符 10、无结果 10；附预期相关笔记 ID。指定精确标题/标签样本应全部命中，人工标注相关集 Recall@10 目标 ≥90%，避免仅测速度不测召回。
- 使用同一 Windows x64 测试机（建议至少 4 核、16GB RAM、SSD），记录实际 CPU/内存/磁盘、OS、应用构建、Electron/SQLite/分词器版本及电源模式。正式指标用打包 release 构建，不用开发服务器。
- 索引完成后预热 20 次，100 条查询固定顺序运行 10 轮；从提交查询到首屏前 20 条结果渲染完成计时，包含分词、IPC、数据库和高亮，不含输入防抖。按 1,000 个样本排序取第 950 个作为 P95，目标 <500ms；另报中位数、最大值、错误数和召回结果。
- 首次启动/冷缓存、首次建索引、全量重建、增量更新单独记录耗时、峰值内存和库大小，不混入热查询 P95。保留脚本、命令、原始计时数据和失败样本，供重复运行。
- 捕获 <1 秒指打开入口到可输入，10 秒指人工完成记录；自动保存 2 秒防抖后原子落盘，未显示“已保存”的内容不计作已持久化。启动 <3 秒从进程启动到窗口可交互，冷/热各 10 次分别报告。
- 编辑边界：普通笔记 ≤100 KiB，中文输入连续 100 次响应 P95 目标 <50ms；1 MiB 长文作为压力样本单报。超过 1 万篇、超大附件、磁盘满/慢盘、并发重建时不承诺上述延迟，但须有进度/错误提示且不能静默丢数据。阈值需用 spike 证据复核，不把建议硬件或未实测数字描述为支持保证。

## 9. 验收流程

1. 选取明确请求或多步任务卡，确定适用验收项。
2. 执行契约仅引用 `AGENT-规则.md`。
3. 提交结果、验证证据和下一步；需要交接时写报告。
4. Owner 按对应项验收，未运行项标记未验证。
5. 通过后在授权范围更新状态；不通过记录失败证据和修复范围，不自动修改未授权文件。

## 10. 不通过处理

| 情况 | 处理 |
|---|---|
| 主线断 | 停止新能力，先修主线 |
| Agent 越界 | 记录失败模式，补规则/任务卡约束 |
| 秘密泄露 | 立即轮换；检查 Git 历史；补 secret scan |
| 数据丢失 | 停止写入；从备份恢复；复盘 |
| 格式漂移 | 补输出契约示例；连续 3 次复验 |
| 性能不达标 | 建基准；先优化搜索/索引 |

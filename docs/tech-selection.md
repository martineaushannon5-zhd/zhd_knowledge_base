# 技术选型：Windows 桌面优先

日期：2026-11-18。状态：技术顾问推荐基线（proposed），可以据此开展最小验证；尚未安装、打包、测性能，不代表所有兼容性已验证。具体版本在 T-001 查官方稳定版与支持矩阵后锁定，不凭文档猜版本。

## 1. 首选技术栈

| 层 | 首选 | 理由与代价 |
|---|---|---|
| 桌面壳 | Electron | TS 贯通主进程与UI、Windows生态成熟；代价是包体和内存较大 |
| 语言/界面 | TypeScript 严格模式、React、Vite | 多 Agent 容易协作，开发和测试工具统一；React UI不承诺直接移植ArkTS |
| 样式 | CSS 变量 + CSS Modules | 复用 design.md 令牌，不先引入大型组件库 |
| 编辑器 | CodeMirror 6 + Markdown预览 | 源码编辑与预览边界清晰；富文本所见即所得后置 |
| Markdown | markdown-it，HTML默认禁用；预览使用DOMPurify清洗 | 防止导入内容与链接导致脚本执行；远程图片默认禁用 |
| 真相源 | Markdown + YAML front matter + JSON元数据 + 本地附件 | 无应用仍可读；集合、标签等必须可从文件恢复 |
| 派生索引 | SQLite + better-sqlite3 + FTS5 | 本地单进程、可重建；原生模块需验证Electron ABI和安装包 |
| 中文搜索 | 应用层中文预分词后写FTS5；索引/查询同一规范 | 默认FTS5 tokenizer不保证中文质量；具体分词库在小试中确认，覆盖短词和中英混合 |
| 状态管理 | React局部状态和必要Context | 先不引入全局状态框架；有真实复杂性再决定 |
| 单测/集成 | Vitest | 文件操作、索引、权限边界、恢复可独立测试 |
| 桌面端到端 | Playwright Electron支持 | 需核对选定版本支持；测试真实窗口，不只网页预览 |
| 包管理/分发 | npm + 锁文件；electron-builder + Windows NSIS | 单一依赖安装流程；首版手动升级，签名与自动更新另行授权 |
| AI P0 | 本地关键词检索 + 授权上下文 + 单一模型适配器 | 接一个用户选择的云API；无云授权则先用假适配器测试，未接模型不能声称AI已验收 |
| AI后续 | 可选Ollama；向量/混合召回在P1 | 不首版同时维护本地模型运行时、向量库和多厂商兼容层 |

不预先引入独立搜索服务、后端框架、Docker、复杂ORM、微服务、插件市场或审计后台。领域模块以TS组织，但文件IO/SQLite/桌面权限放主进程适配层，不为了未来搭建多套工程。

## 2. 为什么暂不选其他方案

- Tauri：更小包体有价值，但额外Rust工具链与插件桥接增加单人维护成本；只有Electron实测不满足已确认资源预算时再评估，不同时开发两套。
- 本地Web服务/PWA：以后复用方便，但首版增加服务启动、浏览器文件权限和安装体验问题，不作为Windows主交付。
- Meilisearch/Typesense：增加进程和分发维护；只有SQLite方案在固定语料上确实达不到质量/性能要求才评估。
- 鸿蒙：未来评估ArkTS原生界面或Web容器；PWA能力取决于目标设备/系统/浏览器，必须真机验证。共享数据协议优先，不承诺Electron、Node、React直接运行于鸿蒙。

## 3. 数据与安全边界

渲染进程不开Node集成，启用contextIsolation和sandbox；preload只暴露窄接口，不暴露任意文件读写或shell。主进程校验参数、IPC来源、vault内规范化路径；限制符号链接/路径穿越，禁止默认读取vault外秘密。禁用任意导航与新窗口，外部链接需确认；设置CSP。

文件先原子持久化，再更新SQLite；索引失败可重试或重建，不能反向覆盖正文。外部编辑冲突保留双方，禁止静默最后写入覆盖。大规模分词、索引、压缩避免阻塞UI及主进程。附件以hash标识共享数据，引用关系独立保存。

云AI只发用户授权内容；文件授权不是网络授权。模型输出及检索到的文档属于不可信内容，不能改变系统规则或直接执行命令。引用必须关联真实笔记ID和片段，没有依据时拒答。

## 4. T-001必须验证

1. 查官方支持矩阵，锁定Electron、Node构建环境、better-sqlite3与打包工具版本；不默认当前系统Node适合全部构建插件。
2. 在含中文与空格路径的临时vault写入/读取Markdown；不使用用户真实资料。
3. 验证SQLite扩展中FTS5可用，原生模块在开发与NSIS安装后均可加载。
4. 打包安装、启动、卸载；记录包体、空闲内存、启动耗时与机器条件。未签名包的系统提示如实记录，不关闭安全保护绕过。
5. 最小窗口实际操作、错误保存提示和控制台检查；有阻塞记录失败，不把候选意见当实测。

## 5. 决策边界

D-001 Electron、D-002 文件真相源+SQLite、D-003 FTS5中文预分词为推荐，实测通过后记录确认；D-004模型提供商/数据外发授权未定。D-005秘密目录、D-006远端同步和D-008鸿蒙路线无需全部确定才开始桌面本地验证。现有AccessKey轮换待确认，任何验证不使用该凭证。

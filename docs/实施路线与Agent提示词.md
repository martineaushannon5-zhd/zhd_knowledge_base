# 实施路线与给 Agent 的提示词

日期：2026-11-18。当前只有文档，没有应用代码。本文是技术顾问推荐路线，不是测试通过证明。

这里的“阶段”是可暂停的验收节点，不排周数、不承诺发布日期。桌面最高优先级；Web和鸿蒙仅在桌面稳定后启动。技术基线见 `tech-selection.md`，工作规则见 `../AGENT-规则.md`。

## 一、阶段与出口

| 阶段 | 做什么 | 技术栈 | 通过后才能做什么 |
|---|---|---|---|
| A Windows最小验证（T-001） | 最小窗口、本地文件IO、SQLite、NSIS安装 | Electron/TS/React/Vite、better-sqlite3、electron-builder | 开始正式数据模块；先查兼容版本，原生模块与打包失败必须解决 |
| B 数据安全底座 | 文件真相源、原子保存、附件、外部修改冲突、备份恢复 | Node文件API、Markdown/YAML/JSON、SQLite派生索引、Vitest | 用临时数据证明保存/恢复/重建；不可先录入唯一真实资料 |
| C 捕获到搜索闭环 | Inbox、编辑、预览、标签集合、中文搜索、保存状态、回收站 | CodeMirror6、markdown-it/DOMPurify、FTS5中文预分词、React/CSS | 实际UI走查，中文一万篇查询基准；不只验证速度，也验证找得到 |
| D Agent交接 | 任务卡、按需Context Pack、执行报告、换Agent接手 | 现有Markdown模板与文件，无额外服务 | 三次真实任务格式与边界可用；别把文档权限当系统沙箱 |
| E 知识库AI | 授权内容检索、问答引用、无依据拒答 | 关键词检索+一个模型适配器；Vitest假适配器测试 | 配置获准模型后才验收真实AI；断网不影响笔记核心功能 |
| F Windows交付 | 干净环境安装、换目录恢复、离线、扫描与版本记录 | NSIS、Playwright、Vitest、文件级secret scan | 个人日常使用；之后才选择Web/鸿蒙、语义搜索等增强 |
| G 后续能力池 | Web访问、鸿蒙、同步、语义搜索 | Web可复用React；鸿蒙ArkTS/Web容器待真机评估；同步另定协议 | 每项独立选型，不因远期平台改造首版核心 |

B的备份恢复不等待E。D可在C之前以文档手工试用，不必为了交接开发任务调度系统。P0 AI是关键词检索结合生成；向量、混合检索、重排属于P1，不作为基本问答的前提。

## 二、现在应该做什么

1. 下一张任务就是 `../cards/任务/T-001-桌面壳选型.md`：只验证首选Electron，不做三套候选。
2. 先查本机可用工具与官方支持版本，明确依赖及安装权限，再创建隔离验证目录。框架推荐不等于批准未知外部脚本。
3. 记录开发运行与安装包运行差异，尤其SQLite原生模块。验收失败先修该阻塞，不扩展业务功能。
4. 通过后再拆B/C，每次一个闭环。AI提供商、秘密目录、远端Git、鸿蒙路线后置；不要一口气要求用户回答所有待决策。
5. Git初始化可另行明确授权；不依赖远端即可实现本地备份，不擅自提交或推送。

## 三、必须补上的实现行为

- **可靠保存**：明确“编辑中/保存中/已保存/保存失败”；2秒防抖不代表未保存输入已经安全。关闭时处理待保存内容，模拟磁盘满、权限不足、杀进程，报告实际数据损失边界。
- **冲突**：内外编辑同时发生保留冲突副本，禁止无提示覆盖；损坏front matter保留原文件并报错，不以空内容重写。
- **数据可搬走**：JSON保存集合/标签等不可派生元数据，删除索引仍能恢复；移动vault后附件相对路径有效。
- **恢复**：在临时目录校验清单/hash再切换，先保留原vault；备份清理须明确保留策略，不默认删用户历史。
- **搜索基准**：记录机器/软件版本、语料生成方式、篇幅分布、至少100条固定查询、冷热缓存与P95定义；覆盖一字/二字/中英混合/特殊字符。速度目标一万篇P95<500ms，相关性阈值在基准建立时明确，不能只用随机文本测速。
- **性能口径**：10秒是完成一条捕获的操作时间；小于1秒是入口响应；2秒是停止输入后的保存调度；启动小于3秒应说明冷/热启动及测量边界。
- **安全**：renderer不直接读文件；IPC白名单、路径与输入校验、Markdown清洗、远程内容默认禁用；知识库里的提示文字不是可执行授权。
- **状态诚实**：假数据测试不等于用户验证，假模型不等于真实AI，打包成功不等于安装成功；每份报告分开记录。

## 四、可以依次复制给 Agent 的提示词

### 1. 现在：Windows验证

> 请执行 cards/任务/T-001-桌面壳选型.md。先读 AGENT-规则.md、当前状态和 docs/tech-selection.md，以Electron推荐基线做一个最小Windows验证，不并建Tauri或Web服务。先查当前工具与官方版本兼容性，列实际需要安装的依赖；遵守工具权限。只在任务允许目录创建验证代码，以临时数据测试中文/空格路径文件IO、SQLite FTS5、原生模块打包、NSIS安装启动和卸载。实际打开窗口走查并记录控制台；记录实测条件和失败，不伪称通过。不要实现业务功能、读取秘密、初始化Git、提交或推送。结束给报告和下一张任务建议。

### 2. 数据底座

> 先读T-001报告；若Windows验证未通过，只解决该阻塞。通过后，先列本次允许文件和测试，再实现最小文件数据层：Markdown/front matter、JSON集合标签、附件相对路径、原子保存和可重建SQLite索引。补临时目录测试，包括外部修改冲突、无权限/保存失败、索引删除重建、迁移目录、备份恢复校验。恢复不覆盖真实资料，清理需授权。不要加云同步、AI、复杂ORM或审计后台。给实际测试结果、未验证边界和下一步。

### 3. 捕获、编辑与搜索

> 按已验证数据层完成一条桌面闭环：新建到Inbox、CodeMirror6编辑、安全Markdown预览、保存状态、标签集合、中文搜索并打开结果。使用设计令牌，避免1280px四栏挤压；核心操作支持键盘。中文分词先验证短词和中英混合，再做一万篇固定基准。运行桌面应用实际操作正常路径、空结果、保存失败和索引损坏场景，检查控制台与回归。不要只凭类型检查宣布完成，不做移动端或知识图谱。

### 4. 多 Agent 交接试用

> 使用现有任务卡、Context Pack和报告模板，完成一次范围明确的真实任务交接。只摘要相关文档与代码事实，不读全库；标记当前执行Agent、已完成项、允许文件、测试证据和下一步。接手时核对当前文件，不覆盖他人工作。缺少能力卡如实说明，无需先造一批卡片。不要开发多Agent调度器。累计三次真实任务验证后再报告契约稳定。

### 5. AI问答

> 先确认我选择的模型提供商和允许发送的内容；没有授权则仅实现假适配器测试，并注明真实AI未验收。实现关键词检索、上下文选择预览、单一模型适配器、笔记ID/片段引用与无依据拒答。禁止上传全库、发送秘密、执行模型输出命令。覆盖无结果、伪造引用、文档提示注入、断网、取消、限流和超时；断网不影响笔记。暂不加向量库或多个模型运行时。

### 6. 交付检查

> 对当前Windows首版做交付验收：实际安装、启动、核心操作、离线、中文路径、备份恢复、索引重建和卸载后的用户数据保留。跑范围内测试与文件级秘密扫描，记录机器与安装包版本。无干净Windows环境则明确未验证，不冒充完成。不要修改系统安全设置、删除用户数据、上传安装包或推送代码。列阻断问题与后续可选能力。

### 7. 换一个 Agent 继续

> 请先读 AGENT-规则.md、当前任务卡和最近工作流报告，再核对实际文件状态。用一句话说明接下来做什么，只继续未完成且已授权部分。发现报告与现状不符先记录差异；不得覆盖前一个Agent的改动，不重复安装或从头重建项目。需要超范围或执行不可逆操作再问我。

## 五、用户何时才需要拍板

现在只需要决定是否按推荐基线进入T-001；执行依赖安装时响应工具授权。之后涉及云AI内容外发、删除/恢复覆盖、部署/推送、鸿蒙设备路线时再决策。此前记录的AccessKey轮换状态仍未知，不在任何开发验证中使用。
